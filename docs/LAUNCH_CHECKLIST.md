# Launch Checklist — Flow, Phase 1

قائمة تحقق للإطلاق التجاري الفعلي (وليس التقني فقط — المنتج GA تقنيًا منذ 2026-08-01، لكن الإطلاق التجاري لم يبدأ). كل بند **ثنائي** (✓ أو ✗ فقط، لا "جزئيًا")، وله **طريقة تحقق محددة** بدل الانطباع — نفّذ طريقة التحقق فعليًا قبل تعليم البند.

طرق التحقق المستخدمة في هذا الملف: **فتح رابط** · **تشغيل اختبار** · **التحقق من إعداد** · **مراجعة سجل**.

## النشر (Deployment)

| البند | طريقة التحقق | الحالة |
|---|---|---|
| المنتج منشور وحي (frontend + backend) | فتح رابط: `/health` و`/health/deep` على الخادم | ✓ |
| HTTPS مفعّل على الواجهة والخلفية | فتح رابط: تأكيد قفل HTTPS في المتصفح على كلا الرابطين | ✓ |
| CORS يسمح فقط بالأصول الصحيحة (لا `*` في الإنتاج) | مراجعة سجل: قيمة `EXTRA_CORS_ORIGINS`/`APP_URL` في إعدادات Render | ✓ |
| مراقبة أخطاء حية مفعّلة (Sentry أو مكافئ) | التحقق من إعداد: وجود مفتاح/SDK مراقبة أخطاء في متغيرات البيئة | ✗ |
| صفحة/نقطة حالة عامة (status page) | فتح رابط: صفحة حالة عامة منشورة | ✗ |

## النطاق (Domain)

| البند | طريقة التحقق | الحالة |
|---|---|---|
| نطاق مخصص (ليس `*.vercel.app`/`*.onrender.com`) | فتح رابط: الدومين الفعلي في متصفح | ✗ |
| بريد على نفس النطاق (مثل `hello@flow.app`) | التحقق من إعداد: صندوق بريد فعّال على النطاق | ✗ |

## البريد (Email)

| البند | طريقة التحقق | الحالة |
|---|---|---|
| بريد ترحيبي/تأكيد عند التسجيل | تشغيل اختبار: تسجيل حساب جديد فعلي وانتظار البريد | ✗ |
| بريد إعادة تعيين كلمة المرور | تشغيل اختبار: طلب إعادة تعيين فعلي وانتظار البريد | ✗ |
| بريد دعم/تواصل يصل فعليًا لصندوق يُراجَع | تشغيل اختبار: إرسال رسالة عبر نموذج/بريد صفحة الهبوط والتأكد من وصولها | ✗ |

## التحليلات (Analytics)

| البند | طريقة التحقق | الحالة |
|---|---|---|
| أداة تحليلات مثبَّتة (Plausible/PostHog/GA) | التحقق من إعداد: سكربت التحليلات ظاهر في مصدر الصفحة | ✗ |
| حدث "تسجيل" مُتتبَّع | تشغيل اختبار: تسجيل حساب ومراجعة ظهور الحدث في لوحة الأداة | ✗ |
| حدث "أول استخدام فعلي" مُتتبَّع | تشغيل اختبار: تنفيذ إجراء فعلي ومراجعة ظهور الحدث في لوحة الأداة | ✗ |

## الفوترة (Billing)

| البند | طريقة التحقق | الحالة |
|---|---|---|
| مزود فوترة واحد مُختار ومُفعَّل (Stripe/Paddle/Lemon Squeezy) | التحقق من إعداد: مفاتيح API فعلية في متغيرات البيئة | ✗ |
| صفحة تسعير عامة بباقتين وسعر واضح | فتح رابط: صفحة التسعير | ✗ |
| تدفق دفع كامل يعمل من بطاقة اختبار حتى وصول فعلي للميزات | تشغيل اختبار: عملية شراء كاملة ببطاقة اختبار | ✗ |

## النسخ الاحتياطي (Backups)

| البند | طريقة التحقق | الحالة |
|---|---|---|
| نسخ احتياطي تلقائي مفعّل لقاعدة بيانات Render المُدارة | التحقق من إعداد: إعدادات Backups في لوحة تحكم Render | ✗ |
| تجربة استعادة (restore) ناجحة موثقة مرة واحدة على الأقل | تشغيل اختبار: استعادة فعلية على بيئة منفصلة | ✗ |

## سياسة الخصوصية والشروط (Privacy & Terms)

| البند | طريقة التحقق | الحالة |
|---|---|---|
| سياسة خصوصية منشورة | فتح رابط: صفحة سياسة الخصوصية | ✗ |
| شروط استخدام منشورة | فتح رابط: صفحة الشروط | ✗ |
| آلية حذف حساب ذاتية تعمل | تشغيل اختبار: استدعاء `DELETE /api/auth/me` فعليًا على حساب اختبار | ✓ |

## أمان — الحد الأدنى قبل أول عميل حقيقي

| البند | طريقة التحقق | الحالة |
|---|---|---|
| Rate limiting وحدود استخدام المنظمة مفعّلة على مسارات AI | مراجعة سجل: `ai_rate_limit`/`check_org_quota` مطبَّقة في `app/routers/` | ✓ |
| لا تعديلات أمنية غير مُلتزم بها في نسخة العمل المحلية | تشغيل اختبار: `git status` نظيف على `app/commands/` و`app/agents/` | ✗ |
| مراجعة أمنية مستقلة أخيرة (SSRF/IDOR/WS-auth) منجزة وموثقة | مراجعة سجل: تقرير مراجعة موقّع أو مذكور صراحة كمكتمل | ✗ |
