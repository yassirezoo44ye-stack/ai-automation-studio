### القرار المقترح قبل تغيير كبير

أوصي بإبقاء Redis الحالية للكاش، وجعل PostgreSQL الموجودة مرجع **إلغاء JWT**، بدلاً من الاعتماد على مفاتيح Redis قابلة للفقد. المقترح للمراجعة فقط؛ لم يُنفذ ترحيل أو تغيير سياسة المصادقة التالية:

1. إضافة `users.auth_version BIGINT NOT NULL DEFAULT 0` بترحيل idempotent.
2. إصدار JWT بclaim رقم إصدار، وقراءة الإصدار من PostgreSQL عند التفويض. يُعامل JWT القديم بلا claim كإصدار0 حتى أول عملية إلغاء؛ المستخدم المحذوف أو اختلاف الإصدار يُرفض.
3. زيادة الإصدار ذرياً داخل transaction نفسها لتغيير كلمة المرور/استعادتها أو إنهاء جميع الجلسات. تُصدر الرموز الجديدة بالإصدار المقروء من القاعدة، دون اعتماد على مقارنة ساعات العمال.
4. تقديم JWT عند وجوده مع X-Sub-Token، ومنع الرجوع للرمز القديم عند رفض JWT. جرد الطلبات التي تعتمد فقط على رمز الاشتراك القديم قبل حصره/ترحيله؛ لا يُدّعى إلغاء تلك الرموز تلقائياً بهذا العمود وحده.
5. عند تعذر قراءة حالة المصادقة من القاعدة: فشل مغلق503، دون الرجوع إلى Redis أو رمز أقدم. يضيف ذلك استعلام PK لكل تحقق؛ يجب قياس أثره محلياً.

معايير القبول: عمليتان مستقلتان؛ إعادة تشغيل التطبيق وRedis وحذف مفاتيح Redis؛ رمز قديم مرفوض بعد الإلغاء ورمز جديد مقبول فوراً؛ تعارض طلبات الإلغاء؛ JWT قديم بإصدار0؛ مستخدم محذوف؛ فشل القاعدة؛ عدم تخطي JWT المرفوض برمز اشتراك قديم؛ توافق تحديث الجلسة والمصادقة ومفاتيح API. تحتاج هذه الخطوة موافقة المالك لأنها تغيّر مصدر حالة المصادقة وتضيف ترحيلاً للقاعدة، وفق شرطه الأصلي بالرجوع إليه قبل التغييرات الكبيرة. النشر يبقى قراراً منفصلاً بعد تنفيذها واختبارها.

### نتيجة إثبات فقدان سجل الإلغاء

أُضيف اختبار مستقل بعمليتين وRedis محلية، يحذف **سجل المستخدم الاصطناعي الفريد فقط** لمحاكاة فقد السجل عند eviction/restart؛ لا ينفذ FLUSH ولا يحذف بيانات Redis أخرى. أكد أن الرمز القديم يمكن قبوله بعد فقد السجل. الاختبار موسوم strict expected-failure لنوع الخطأ الأمني المحدد فقط؛ أعطال إعداد الاختبار أو الاتصال لا تُخفى كنجاح متوقع. يجب تحويله إلى اختبار ناجح بعد تطبيق المرجع الدائم، وليس إزالة فحصه.

نتائج المتابعة المحلية: **74 passed و1 xfailed** في مجموعة التفعيل والكاش وإلغاء JWT والانحدار/المراقبة؛ وإعادة المجموعة المركزة على الاختبارات الجديدة **23 passed و1 xfailed**. الفشل المتوقع **مشكلة مفتوحة تمنع التفعيل**، وليس حماية ناجحة. نجح Ruff وwhitespace check. أرقام3461/587 وCI السابقة أعلاه تخص الالتزام السابق؛ تُسجّل نتائج الالتزام المحدّث في وصف طلب الدمج عند اكتمالها.
