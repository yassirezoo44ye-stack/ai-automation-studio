# مهارات تطوير Flow

هذه خريطة اختيار للمهارات الخارجية المقترحة، وليست نسخًا مثبتة منها. توافرها يتبع بيئة المساعد والإضافات المتصلة. لا تُنسخ تعليمات إضافة خارجية إلى المشروع على أنها قدرة تعمل داخل Flow.

| المهارة | متى تُستخدم | نطاق Flow |
| --- | --- | --- |
| `audit-repo-readonly` | تدقيق الأدلة قبل التعديل أو الإصدار | Git وCI والتكاملات والجاهزية؛ التدقيق وحده للقراءة فقط |
| `build-agents` | تصميم وكيل أو توزيع مسؤوليات وأدوات | مراجعة محرك الوكلاء الحالي قبل اختيار إطار جديد |
| `create-a-backend` | تصميم واجهات وحدود الخدمات | Python وFastAPI، مع التحقق من توافق أي توصية خاصة بمنصة |
| `react-best-practices` | مراجعة مكونات الواجهة المعدلة | React وTypeScript وحدود الميزات في `src/renderer` |
| `verification` | اختبار الرحلة كاملة | المتصفح ثم API ثم البيانات ثم الاستجابة |
| `render-workflows` | تقييم أو تنفيذ سير عمل دائم على Render | تحقق من توافق SDK مع المحرك الحالي؛ لا تستبدله تلقائيًا |
| `render-background-workers` | المهام الطويلة واستهلاك الطوابير | راجع `app/core/jobs` و`app/core/workflow` أولًا |
| `render-postgres` | اتصالات PostgreSQL والتخزين والنسخ الاحتياطية | راجع إعدادات DB الفعلية ولا تفترض وجود نسخة احتياطية |
| `render-debug` | تشخيص نشر Render | `render.yaml` والسجلات والفحوص الصحية |
| `deployments-cicd` | نشر Vercel أو مراجعة مسار النشر | `vercel.json` و`.github/workflows` |

## ترتيب العمل

ابدأ بتقييم الحالة، ثم حدّد المهمة ونطاق التعديل، ثم اختر المهارة الملائمة. لا تشغّل نشرًا أو ترحيل بيانات لمجرد أن المهارة متاحة. التزم بالتفويض القائم، واطلب فقط المعلومة أو الإذن الناقص فعليًا.

## تحقق يناسب التغيير

- الواجهة: أوامر `typecheck` و`lint:strict` واختبارات Vitest والبناء بحسب الملفات المعدلة.
- الخلفية: اختبارات pytest المناسبة وفحص Ruff بحسب النطاق.
- المسارات المتكاملة: تحقق من المصادقة وعزل المؤسسة والأخطاء وحفظ البيانات باستخدام بيئة اختبار.
- ملفات المهارات فقط: صحة بيانات التعريف وروابط الملفات واكتمال الأقسام و`git diff --check`؛ لا يلزم تشغيل التطبيق.

راجِع `README.md` و`DEPLOYMENT.md` قبل تعديل المخطط: توثيق المستودع يذكر أن التهيئة عند بدء التشغيل هي مسار تغييرات المخطط الحالي، مع قيود في سلسلة Alembic.

## حدود التوافق

مهارات `ai-sdk` و`auth` الخاصة بـ Vercel ليست بديلًا تلقائيًا لتكاملات Python والمصادقة الحالية. قيّم الحاجة والتوافق قبل إدخال SDK أو إطار جديد. مهارات البيانات مفيدة للتقارير عند توفر مصادر فعلية؛ لا تعرض بيانات عرض تجريبية كقياسات تشغيلية.
