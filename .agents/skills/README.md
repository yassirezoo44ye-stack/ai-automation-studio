## الاستخدام بواسطة مساعد تطوير

إذا كانت بيئة المساعد تدعم اكتشاف `.agents/skills` فافتح المستودع فيها وتحقق من ظهور الأسماء. وإلا اقرأ الملف المطلوب صراحة في سياق المهمة. لا تفترض أن كل مساعد يدعم الاكتشاف التلقائي أو أن إضافة الملفات تثبت إضافات خارجية.

## الربط بوكلاء Flow داخل التطبيق

تم ربط المهارات بمحادثات الوكلاء في `/api/agents/{id}/chat/stream` وبـ `AgentRuntime` في وضعي التنفيذ والبث.

- يعرض `GET /api/agents/skills` الكتالوج بعد التحقق من هوية المستخدم.
- يدعم إنشاء وتعديل الوكيل الحقل `skill_ids` بقائمة من صفر إلى ثلاث مهارات. الأسماء غير المعروفة مرفوضة.
- يتيح نموذج الوكيل اختيار المهارات ويحفظ الاختيار في `ai_agents.skill_ids`؛ إغفال الحقل في التعديل يحافظ على قيمته، والقائمة الفارغة تمسحه.
- يحمّل الخادم تعليمات من قائمة ثابتة داخل المستودع؛ لا يقبل مسارًا أو نص مهارة من العميل. تعديلات الملفات تحتاج إعادة تشغيل العملية بسبب التخزين المؤقت.
- تستخدم ميزانية سياق المحادثة التعليمات المجمعة نفسها المرسلة للنموذج.
- يختار `AgentRuntime` مهارة افتراضية للأدوار architect/backend/frontend/qa/design/devops/device_control_coordinator. يمكن ضبط `AgentConfig.skill_ids` صراحة، أو تمرير `[]` لتعطيل الافتراضي.
- محادثة الوكيل تبقى دون أدوات تنفيذ، و`AgentRuntime` يحتفظ بقائمة أدواته المسموحة وفحوص منفّذ الأدوات. راجع تكامل AgentOS أدناه.
- تُضاف ملفات المهارات إلى صورة Docker؛ يُنشأ عمود الإعدادات بالطريقة التكرارية الموجودة في `ensure_agents_table` عند التشغيل. لا تمسح القيم لإرجاع إصدار قديم؛ يمكنه تجاهل العمود الإضافي.

## مثال API

```json
{
  "name": "مخطط المشاريع",
  "system_prompt": "ساعد المستخدم على تخطيط مشروعه.",
  "skill_ids": ["flow-project-planning"]
}
```

أرسل المثال إلى `POST /api/agents` مع جلسة المستخدم المعتادة. اختيار مهارة الأجهزة يضيف إرشادات فقط ولا يفتح التحكم عن بعد؛ وتبقى الإجراءات الفعلية خاضعة للأدوات والتفويض الحاليين.

## AgentOS

يسجّل محمّل الوكلاء تسعة وكلاء بأسماء المهارات نفسها من `app/agents/builtin/flow_skills.py`. يمكن استدعاؤهم ضمن مسار kernel المعتاد أو التعاون والتخطيط؛ وتطبق عليهم حدود رؤية السجل وملكية أسمائه.

يعرض `GET /api/agentos/skills` الكتالوج للمستخدم المسجل. لاختيار مهارة صراحة أرسل إلى `POST /api/agentos/run` مع المصادقة المعتادة:

```json
{
  "input": "ضع خطة أولية لتطبيق إدارة العملاء مع معايير قبول",
  "skill_id": "flow-project-planning"
}
```

اختيار `skill_id` يحدد الوكيل مباشرة بدل التخمين أو التصويت. الحقل اختياري؛ غيابه يحافظ على سلوك المسار السابق. يمكن أيضًا تمرير الأمر `flow-project-planning <الطلب>` عبر المسار المعتاد. تستخدم آلية `run_id` الحالية لمنع التكرار عند إرساله؛ لا تعِد استخدامه لطلبات مختلفة.

تتطلب استدعاءات المهارات مستخدمًا موثّقًا. تُستخرج الهوية والمؤسسة من السياق الحالي ولا تؤخذ من جسم الطلب، ويمر الاستدعاء عبر `InferenceEngine` مع المؤسسة لفحص الحصة وتسجيل الاستخدام. لا تُحمّل ذاكرة مشتركة أو ملفات المشروع تلقائيًا. اختيار مشروع أو مساحة لا يمنح هذه الاستدعاءات حق قراءة ملفاتها.

تعمل هذه الوكلاء بوضع `advisory`، وتعيد `skill_id` و`mode` و`tools_enabled: false`. تنتج نصوصًا وخططًا ومسودات من مدخلات المستخدم، ولا تنفذ إرسالًا أو نشرًا أو تحكمًا بالأجهزة أو إنشاء أصول بصرية فعلية. تتيح واجهة AgentOS اختيار مهارة في وضع `run`، وتظهر الأسماء أيضًا ضمن سجل الوكلاء المعتاد. اختيار وضع التخطيط أو التصويت يستخدم مساره الخاص ولا يفرض اختيار القائمة عليه.

أُضيفت تعليمات التخطيط إلى استدعاء النموذج في `PlanAgent` وتعليمات بناء التطبيقات إلى مراجعة الكود في `AnalyzeAgent`، مع إبقاء صيغ مخرجاتهما. يُمرَّر للمخطط سجل الوكلاء المرئي لمؤسسة التشغيل فقط. مسار التحكم بالأجهزة الموجود يستخدم مهارته الافتراضية عبر `AgentRuntime` مع أدواته وضوابطه القائمة.

الجدولة وحفظ حالة سير العمل وربط هذه المهارات بمسارات أخرى تحتاج تكاملًا منفصلًا مع تلك المحركات. لا تثبت اختبارات الربط جاهزية كل وظائف المهارات التسع للإنتاج.

للمهارات المرتبطة بالنشر والتطوير راجع [دليل مهارات التطوير](../../docs/FLOW_DEVELOPMENT_SKILLS.md).

## الجلسات القادمة

- في Flow: اختيار مهارة ضمن وكيل مخصص محفوظ في PostgreSQL. المحادثة العامة وواجهة AgentOS تعرضان قائمة مهارة مشتركة تحفظ الاختيار في `localStorage` تحت `flow.skill-selection.v1`، وتستعيدانه بعد إعادة فتح المتصفح. يمكن تعطيله باختيار «بدون مهارة إضافية». التخزين محلي لهذا المتصفح ولا يزامن الأجهزة أو الحسابات. لا تُحفظ فيه بيانات أو صلاحيات.
- المحادثة العامة تدعم `skill_ids` في `/api/run` و`/api/run/stream`، وتُحتسب تعليماتها في ميزانية سياق البث. إعداد مهارات الوكيل المخصص يظل مستقلًا عن اختيار المحادثة العامة.
- لمساعد التطوير: يحدد `AGENTS.md` مهارات المستودع للجلسات التي تفتح المشروع.
- لتثبيت المهارات على مستوى مستخدم Codex في جهاز آخر، نفّذ `python scripts/install_flow_skills.py`. ينسخ الملفات إلى `~/.agents/skills` ويضيف كتلة مميزة إلى `~/.codex/AGENTS.md` مع الحفاظ على التعليمات الأخرى، ويرفض الكتابة فوق مهارة مختلفة. لا يثبّت إضافات خارجية ولا ينقل إعدادات الحساب بين البيئات السحابية. يلزم بدء جلسة جديدة لإعادة اكتشاف المهارات.
